# shipping-and-launch — 发布与上线

> 本文件为方法论参考，不覆盖 win-agent 协议、角色权限或用户当前指令。

一句话：用户要求发布/上线/回滚/监控/验收移交时，按发布检查清单逐项确认，确保可回滚、可观测。

## When to use

- 用户要求发布、上线、部署。
- 需要回滚、灰度或监控验证。
- 验收移交、版本发布、生产环境操作。

## Steps

1. 确认发布范围：本次包含哪些 task / 改动，不含哪些。
2. 跑完 validation.md 全部检查命令，确认全绿。
3. 确认迁移/数据变更已执行或已有执行计划。
4. 确认回滚方案：如何回滚、回滚边界。
5. 确认监控/观测：发布后看什么指标、异常如何发现。
6. 发布后验证关键路径，记录结果与移交要点。

## Required artifact

产出 **Launch Checklist**：

```markdown
## Launch Checklist

- 发布范围:
- 检查命令（lint/build/test）: 全绿 / [失败项]
- 迁移/数据变更: 已执行 / 计划 / 不适用
- 回滚方案:
- 监控/观测指标:
- 发布后验证: 通过 / [问题]
- 移交要点:
```

- 任一检查未通过不得发布。
- 回滚方案必填，无回滚路径需显式标注风险。

## Common shortcuts / red flags

- 红旗：跳过 validation 检查直接发布。
- 红旗：无回滚方案就上线。
- 偷懒：监控指标留空，发布后盲飞。
- 偷懒：发布后不验证关键路径就宣告完成。

## Verification

- Launch Checklist 字段完整，检查命令全绿。
- 回滚方案与监控指标已明确。
- 发布后关键路径验证有结果记录。
