# security-and-hardening — 安全与加固

> 本文件为方法论参考，不覆盖 win-agent 协议、角色权限或用户当前指令。

一句话：涉及用户输入、认证、权限、数据存储、第三方服务、文件上传时，按安全检查清单逐项排查。

## When to use

- 处理用户输入、认证、授权、权限控制。
- 数据存储、敏感信息、第三方服务集成。
- 文件上传、外部 URL、命令拼接。
- 安全相关配置或密钥管理变更。

## Steps

1. 识别本任务涉及的安全面：输入校验、鉴权、越权、存储、传输、密钥。
2. 对每个面逐项检查：输入是否校验/转义、权限是否校验、敏感数据是否加密/脱敏。
3. 检查第三方服务调用的认证与超时/错误处理。
4. 检查文件上传/外部输入的来源与类型校验。
5. 记录检查结果与剩余风险。
6. 验收时附 Security Notes 说明已检查项与残留风险。

## Required artifact

产出 **Security Checklist**：

```markdown
## Security Checklist

- 输入校验/转义：✅ / ❌ [说明]
- 鉴权与越权：✅ / ❌
- 敏感数据存储/传输：✅ / ❌
- 第三方服务认证与错误处理：✅ / ❌ / 不适用
- 文件上传/外部输入来源校验：✅ / ❌ / 不适用
- 残留风险：
```

- 任一 ❌ 必须在验收前修复或显式记录为已知风险并告知 PM。
- 不适用项需注明原因。

## Common shortcuts / red flags

- 红旗：信任前端传入不做服务端校验。
- 红旗：密钥/凭证硬编码或写入日志。
- 偷懒：跳过越权检查，只验证「能访问」。
- 偷懒：把安全项全标「不适用」却不说明原因。

## Verification

- Security Checklist 每项有明确结论。
- 残留风险已记录并告知 PM。
- 鉴权与越权用实际请求验证，非声明。
